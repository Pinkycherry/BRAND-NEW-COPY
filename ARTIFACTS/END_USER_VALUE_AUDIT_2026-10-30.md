# BusinessIdea.io — end-user value audit and product direction

**Date:** 30 October 2026, India time  
**Scope:** Codex-created founder workbenches, discovery pages, tool/resource hubs and failure-research destinations. This audit deliberately excludes the founder's existing articles, authored guides, existing calculators and glossary content, except where a generated page links to them.  
**Method:** Source-code and handover audit. The available browser tool could not open the public Vercel pages, so live rendering, deployed interaction and phone-width screenshots are not claimed as verified. A source implementation is not proof that a feature works for users.

## Executive verdict

BusinessIdea.io should not try to become another AI-credit website. Its strongest product is a **local-first founder workspace that carries a founder's chosen idea and constraints across the site, then hands a carefully prepared prompt to an AI service the founder already uses**.

The platform's own value is the combination of:
- Published business-idea records and categories that give an external AI a concrete starting point.
- A shortlist of up to four ideas, saved in the user's browser rather than in our database.
- The founder's actual constraints: budget in rupees, location, time available, skills, customer access, intended language and delivery limits.
- Specific actions: compare ideas, pressure-test one idea, prepare a first-customer conversation, check time fit, record a decision, or plan the next evidence gate.
- A transparent provider handoff to ChatGPT, Claude, Grok and Perplexity, without paying for inference through our own API.

The core gap is not that every page needs more explanation. It is that several pages explain a decision but do not let the founder carry out that decision. Some pages are mostly link directories; some declare input state in code but render a read-only checklist rather than an actual input. The most promising existing feature is the per-idea Validate button: the current source builds a structured prompt from a published idea, URL-encodes it into a provider-specific query string, and opens one of four providers (Claude, Perplexity, ChatGPT or Grok). This is already a direct prefilled-prompt handoff in the source, not a hypothetical feature. Keep it and expand it into the common shortlist/comparison journey. The approved provider set remains those four services.

## The proposed user journey

1. **Discover.** The founder filters actual published ideas by category, investment band, available time and skill; or searches the catalogue.
2. **Save.** They add up to four published ideas to a shortlist. The shortlist and optional constraints live in browser local storage, not the BusinessIdea.io database. The same shortlist is visible on the comparison, validation and next-step pages on that browser/device.
3. **Set the real-life constraints.** They can optionally enter their city/market, available cash in rupees, hours per week, skills, type of buyer and preferred output language. Do not demand every field before allowing exploration.
4. **Choose a job.** One idea: pressure-test it. Two to four ideas: compare them on the same evidence. A chosen idea: prepare a first-customer conversation. A committed idea: check time/cash/fulfilment or plan the next evidence gate.
5. **Review the prompt.** Show the exact prompt before the founder leaves. It should contain selected source records plus the founder's context, separate known information from assumptions, ask for current sources and publication dates, and explicitly instruct the model not to fabricate market sizes, local costs or certainty scores.
6. **Choose a provider.** Preserve the current prefilled URL handoff for ChatGPT, Claude, Grok and Perplexity. These links put the prepared prompt into the selected service's composer/query flow when accepted and available to the user. A prefilled prompt is not automatically submitted. Keep a copy/open fallback only for a real provider/browser failure or prompt-length limit.
7. **Continue.** When the founder returns, the shortlist and decision context remain available locally. They can record a finding, update one assumption, export their notes, select the next action, or clear their local data.

This model avoids BusinessIdea.io AI inference charges. It does **not** guarantee unlimited free use of external models: provider access, free quotas and features vary. The founder must use their own account where required. Text can be passed in the prompt; images, voice recordings and other attachments cannot be silently transferred by a URL. The founder would upload or dictate those directly in their chosen AI app.

## Purchased reference package versus our actual value

The bought reference package contains useful **architectural ideas**: a founder-tool directory, templates, a market-research flow, a failure-research page, framework comparisons and case-study composition. It is a source of ideas for the type of product, not proof that every displayed number or claim is safe to republish.

The current React routes do not yet realize several of those jobs:
- The current templates route links to six pages instead of delivering a genuine editable/downloadable template collection.
- The current case-study data is explicitly placeholder/composite data and is filtered out; there is no verified success-story dataset currently powering the React case-study page.
- The India failure route is a four-link hub, not a failure database or explorer.
- The market-research/open-source/framework routes are currently guide/route directories rather than full working tools or comparison objects.
- Correction after founder clarification: the current ValidateButton/getValidateUrl source uses URL-encoded prompt query parameters for ChatGPT (`?q=`), Claude (`/new?q=`), Perplexity (`/search?q=`), and Grok (`/?q=`); it intentionally opens a prefilled provider prompt. The missing pieces are shared multi-idea shortlist/context and browser verification of provider-specific prefill flows—not a general lack of prompt-prefill support.

Do not copy the bought source package's unverified headline counts, money-loss claims, success probabilities, fake founder stories, U.S.-specific assumptions or seller branding. A failure collection needs individual source records, source URLs, dates, geography, the particular failure mechanism, limits on what the evidence proves, and an explanation of what a small Indian founder can test. The checked React data file has five placeholder case studies; no verified case should be fabricated to make the grid look populated.

| Priority | Work | User-visible result |
|---|---|---|

| **P0** | Real Compare workbench | Compare 2–4 published ideas side by side on source-grounded fields and the founder's own constraints, then pass the full brief to a chosen LLM. |
| **P0** | Common AI prompt/handoff component | ChatGPT, Claude, Grok and Perplexity; prompt preview, provider-specific prefilled links, prompt review, resilience fallback and no claim of automatic submission. |
| **P1** | Real validation brief, not a duplicated guide | Buyer, last occurrence, current workaround, offer, price and evidence question become a concise local prompt/field brief that the founder can take to an actual buyer and an LLM. |

| **P1** | Time fit and demand-test objects | Actual hours/offer/test fields produce transparent calculations or copyable briefs; no generic verdict or invented benchmark. |
| **P1** | Failure explorer and case-study evidence quality | Global/India case records show real, attributable facts and limitations. If sources are not verified, the page says so instead of inventing statistics. |
| **P2** | Templates, framework comparison, topics, market-research and open-source hubs | Each hub either performs the task promised by its title or is honestly labelled as a directory and demoted from the main conversion path. |

## Local storage and prompt privacy

- Save only the shortlist, optional constraints and notes the founder explicitly chooses to keep. Do not write user input to Supabase and do not store AI transcripts on the BusinessIdea.io server.
- Explain that browser-local data stays on that browser/device; clearing site data or switching devices can remove it. Provide “Export”, “Clear saved data” and “Remove idea” controls.
- Do not send personal context to an external model until the founder explicitly chooses a provider and accepts the prompt handoff. Show what will be sent first.
- Do not promise that image attachments or voice recordings follow the prompt link. The founder can upload or dictate those directly in their own AI account.
- Preserve the global noindex hold on all preview routes and assets. Never make launch/indexing changes as part of this feature.
