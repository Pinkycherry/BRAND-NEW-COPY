## The reader's journey

Start with a real-life constraint → discover a published idea or category path → understand buyer, work and money → calculate a first version → test a specific offer → decide to proceed, change or stop → read a source guide or return to another idea. At each hinge, embed one useful question, tool or preview and a working destination. A generic row of identical "related" links is not engagement.

Every page needs an answer in the opening screen; a substantive method or source-backed example; an interactive or inspectable decision object where useful; the reason that object can mislead; a contextual route to the next question; and a final honest action. Use varied compositions and a readable prose measure while the adjacent width contains a worksheet, original source image, table or preview. Phone layout stacks intentionally with 44px controls. All original typography-bearing artwork stays fully visible in a 16:9 contain stage. One H1 and meaningful H2s; accurate SEO title, description, alt, source attribution and relevant links. No invented market size, success score, testimonials, unsupported idea count or tool output.

## Site frame and navigation

- **Global header:** Explore (Browse, published Blueprints, First Move, five situation-led shelves); Learn (Guides, Journal, Glossary, Reading Room); Tools (Calculator hub, Toolkit, Validation, cost/pricing/cash worksheets); About (Story, founders, contact, truthful access). The desktop groups disclose on click and keyboard; phone uses compact groups, not a long wrapped line. Add links only after the destination works.
- **Footer:** One clear continuation suited to current page where practical; grouped source and decision routes, help/legal links, working contact, no invented social proof. It must never bury the library and tools.
- **Reading rail:** On long guides, posts and ideas, a source-specific contents list, current question, one mid-read detour, another later decision, and a next step. Never cover body text or images with sticky overlays.
- **Image system:** Preserve all source guide/post assets and published idea/category imagery. Store accurate alt, dimensions and SEO context; no cropping of baked text, stretching or placeholder art. Preview image responses remain X-Robots-Tag noimageindex as well as noindex.
- **Global search hold:** Every preview page/post/URL and asset stays noindex. Do not release sitemap or canonical indexing merely because the public domain is connected. Audit the actual domain separately with founder authorization.

## Link and redirect contract

“Redirecting” has two distinct jobs. **Contextual internal paths** move a reader to the next question while preserving the current article. **HTTP redirects** preserve old URLs when a page address changes. Do both deliberately.

1. Keep published /idea/:slug, /startup-guides/:slug, /blog/:slug, /calculator/:slug and approved /category/:categorySlug/:subcategorySlug addresses. Do not rename the 879/20/23/60 source routes for SEO cosmetics.
2. Create each new decision/shelf destination with complete content and QA before placing it in a shared menu, image tile or repeatable widget. Every link receives a descriptive question-specific label, not “Learn more”.
3. Make a route graph: Home/First Move → shelf/category/catalog → real idea → buyer/cost/time/demand tool → guide/related real idea → next decision. Add reverse paths to parent/sibling without trapping the visitor in repetitive CTAs.
4. Audit legacy source URLs against the current route inventory. Record exact old URL, current destination, whether content is identical, owner, and HTTP test in a redirect register. Only after verifying a one-to-one replacement, add a 301/308 from the old same-host path, avoid chains/loops, and preserve query strings when appropriate. Never redirect a missing idea to a generic homepage. A cross-domain bbusiness.online redirect requires control of that origin and a separate migration decision; this repository alone cannot force it.
5. Keep one canonical URL per content page when the real domain is authorized. During preview, noindex plus the response-level X-Robots-Tag still applies to HTML and assets. Leave XML sitemap empty; do not flip indexing in a page-by-page edit.
6. Check every destination in header, footer, cards, breadcrumbs, in-article widgets, images and validation button; follow the destination to verify content and no 404/500. A Vercel green build alone is not a route check.
